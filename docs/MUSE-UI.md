# Muse를 참고한 UI 개편

## 디자인 방향

학교 문서를 비교하는 데스크톱 도구를 흰 바탕, 부드러운 회색 구획, 둥근 패널과 캡슐형 선택 버튼으로 개편한다. Meta Muse의 공식 디자인 소개에 공개된 Goals·Activity 화면을 시각적 참고로 사용한다. Meta 공식 컴포넌트나 디자인 시스템을 사용한 것은 아니다.

- 참고: https://introducing.muse.ai/
- DESIGN_VARIANCE: 4 / MOTION_INTENSITY: 2 / VISUAL_DENSITY: 5
- 기존 Electron·HTML·CSS 구조와 로컬 프리텐다드 400/600을 유지한다.
- 색: 흰색과 중립 회색, 검정 본문, 파란 선택·포커스 표시. 오류·주의 상태는 의미가 구별되는 색과 텍스트를 함께 쓴다.
- 모서리: 작업 패널 22px, 근거·입력 영역 14px, 버튼·필터는 캡슐형.
- 움직임: 상태 전환과 대화상자 표시의 짧은 피드백만 사용하며 동작 줄이기를 지원한다.

## 기존 화면 점검

1. 녹색 제목 표시줄·사이드바·패널 제목과 두꺼운 상단 선이 작업 영역을 잘게 나눈다.
2. 첫 화면의 큰 문서 사진과 56px 제목이 파일 추가보다 많은 공간을 차지한다.
3. 검토 목록과 원본 근거가 같은 선·배경 처리라 읽는 순서가 약하다.
4. 현재 파일 추가 → 문서 검사 → 차이 확인의 흐름, 세 패널, 문서별 큰 비교 값, 직접 수정 대화상자는 유지할 가치가 있다.

이번 개편은 화면의 시각적 표현에 집중한다. 앱 이름·브랜드 마크·기능·메뉴 명칭·버튼 식별자·검사와 저장 방식은 유지한다. 첫 화면은 파일 추가를 중심으로 정리하고, 결과 화면은 목록의 선택 상태와 원문 근거를 분명하게 구분한다. 설정과 저장·수정 대화상자에도 동일한 색과 모서리 규칙을 적용한다.

테이스티 스킬의 범위 제한에 따라 도구형 검토 화면에는 마케팅 페이지의 이미지·애니메이션 규칙을 강제하지 않는다. Muse의 캐릭터·로고·제품 스크린샷을 앱 자산으로 복제하지 않는다.

## 확인 결과

2026-10-09, 버전 1.4.0.

- 단위 테스트 53개 통과. 개발 실행 UI 테스트 12개와 패키징한 EXE의 UI·업데이트 전송 테스트 13개 통과.
- 1440×960 및 최소 창 1100×740에서 첫 화면·검토 목록·원문 근거·직접 수정·설정을 확인했다. 최소 창의 첫 화면도 스크롤 없이 들어온다.
- 프리텐다드 실제 로딩, 키보드 포커스, Esc 닫기, 동작 줄이기, 파일 추가·끌어놓기, 직접 수정·저장·재검사와 오류 복구를 확인했다.
- 주요 글자 대비: 본문 17.56:1, 회색 바탕의 보조 글자 5.40:1, 링크 4.79:1, 기본 버튼 17.56:1, 주의·오류 6.28:1 / 5.98:1.
- 기존 밝은 테마를 유지하며 어두운 테마를 추가하지 않았다. 화면의 네트워크 차단과 로컬 문서 처리는 동일하다.
- 최종 ASAR의 app/·src/ 코드와 1.4.0 버전이 작업 소스와 일치한다.
